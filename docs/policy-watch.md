# 정책·세제 변경 감지 체크리스트 (policy-watch)

이 문서는 **주간 스케줄 에이전트(정책 변경 감지 루틴)의 점검 명세**다. 사람도 이대로 수동 점검 가능.

## 루틴이 매주 할 일
아래 각 항목을 **공식 출처와 대조**한 뒤:
- **값이 바뀌었으면** → 해당 코드 상수 + `src/lib/policyLoan.ts`의 `POLICY_META.effectiveLabel` 갱신 **PR 생성**(이 표의 출처 링크를 PR 본문에 첨부). **자동 머지 금지** — 사람이 PR 리뷰 후 머지 = 승인.
- **값이 그대로면** → `src/lib/policyLoan.ts`의 `POLICY_META.lastVerified`를 점검일로 갱신(커밋). → 결과화면/첫화면의 "최신 점검됨" 배지가 정직하게 유지됨.
- 한도·세율은 **시점 의존**이라 단정 금지 — 불확실하면 PR 대신 "확인 필요" 보고만.

기준 시점: **POLICY_META.lastVerified = 2026-05-26** · 반영: 2025.6.28 개정(디딤돌 한도) + 2025.10.16 스트레스 DSR 3단계 수도권 +3.0%p

> ✅ 주택가격 요건(신생아 9억·신혼 6억·일반 5억·보금 6억): **D2(2026-05-31) — 매수 희망가(targetPriceKrw) 알 때 자격 게이트로 반영**(`evaluatePolicyLoans(profile, {targetPriceKrw})`). 매수가 미상이면 종전대로 reason 안내만. 상수 갱신 시 `policyLoan.ts` SHINSEONA/DIDIMDOL_*/BOGEUMJARI_PRICE_LIMIT 함께 점검.

## 점검 차원 (값 외)
표 점검 시 다음 *차원*까지 능동적으로 보아야 한다. 값만 보면 차원 누락이 통과한다(2026-05-26 토허제·지역 차등 누락 사고 재발 방지).
- **값**: 한도·요율·금리 같은 숫자.
- **지역 차등**: 시군구별로 동일한지/다른지. 코드의 "전 지역 일괄 가정"은 의심하라.
- **허가 절차**: 매수 전 사전허가·사후 의무(실거주·전매제한 등). 값 아닌 *프로세스* 규제.
- **시점 의존**: 시행일·경과조치(계약 전 후 적용). 값이 시기별 다르면 행 두 개로.

## 처리 이력 / 미결
1. ✅ **중개보수 요율**(`calcBrokerRate`) — 2026-05-25 공식 구간(2~9억0.4%/9~12억0.5%/12~15억0.6%/15억↑0.7%)으로 정정 + 잠금 테스트 추가.
2. ✅ **디딤돌 신혼 주택가 reason** — 2026-05-25 5억→6억 정정.
3. ✅ **스트레스 DSR 수도권 +3.0%p 반영** — 2026-05-26: `STRESS_RATE` 5.5→7.0(=4.0+3.0)으로 상향. 2025.10.16 스트레스 DSR 3단계 시행분(수도권·규제지역 주담대). 앱이 수도권 전용이라 일괄 적용. DSR 대출 추정이 ~15% 줄어드는 게 정상.
4. ✅ **LTV 가격대별 캡 정밀 적용** — 2026-05-26: `estimateBudget`에 `opts.targetPriceKrw` 추가, 알려지면 ≤15억 6억/15~25억 4억/25억↑ 2억 캡 적용. 플랜·티어별로 정밀 LTV. 추천 엔진은 보수적 단일 6억 폴백(타깃가 미상).
5. ✅ **보금자리 자녀가산** — 2026-05-26: `BOGEUMJARI_{1,2,3}CHILD_INCOME_LIMIT`(8천/9천/1억) + 다자녀 한도 `BOGEUMJARI_MULTICHILD_LOAN_LIMIT`(4억) 코드 반영. 자녀 수는 프로필 플래그(`hasThreeOrMoreChildren`/`hasTwoOrMoreChildren`/`hasInfant∥hasSchoolAgedChild`)에서 보수 추정.
6. ✅ **2025.10.15 대책 반영 — 지역 차등 + 토허제 + LTV 매트릭스 정정** (2026-05-26):
