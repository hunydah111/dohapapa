# 법적 컴플라이언스 체크리스트

이 문서는 컴플라이언스 패널 검토 결과를 정리한 것으로, 프로젝트가 계속 준수해야 하는 원칙을 체크리스트 형태로 기록합니다. 기능 추가·변경 시 이 항목을 먼저 확인하십시오.

---

## 1. 서비스 성격 및 표현 규제

- [ ] 사용자 대면 문구에서 "추천"이라는 단어를 사용하지 않는다. "조건에 맞는 단지", "정보 제공", "참고용" 등의 표현을 사용한다.
- [ ] 결과가 부동산 중개 행위가 아님을 명확히 한다. 개별 매물을 특정하거나 계약을 유도하는 기능을 추가하지 않는다.
- [ ] 서비스가 투자 자문에 해당하지 않음을 명확히 한다. 미래 가격 예측, 수익률 전망, 자산 증식 시뮬레이션을 제공하지 않는다.
- [ ] 대출모집 행위에 해당하는 기능을 추가하지 않는다. 특정 금융기관 상품 링크, 비교, 가입 유도 UI는 허용하지 않는다.

## 2. 정보 제공 범위

- [ ] 결과는 단지(아파트 단지) 레벨까지만 제공한다. 호·동·층을 특정한 개별 매물 알선으로 이어지는 기능을 추가하지 않는다.
- [ ] 미래 가격 예측 기능을 추가하지 않는다. 현재 실거래가 중위값을 기준으로 한 "현황 정보"만 표시한다.
- [ ] 예산 추정 결과에는 반드시 "추정" 레이블을 표시한다. `BudgetEstimate.isEstimate` 가 `true`인 값만 화면에 표시하고, 실제 대출 한도가 금융기관 심사에 따름을 사용자에게 안내한다.

## 3. 면책 고지

- [ ] `RecommendationResult`를 렌더링하는 모든 화면에서 `DISCLAIMER` 문구를 항상 표시한다. 고지를 숨기거나 닫을 수 있는 UI를 만들지 않는다.
- [ ] 면책 고지 문구(`src/types/recommendation.ts`의 `DISCLAIMER`)를 임의로 단축하거나 삭제하지 않는다. 문구 변경이 필요한 경우 법무 검토 후 반영한다.

## 4. 개인정보 및 데이터 처리

- [ ] 사용자 프로필(소득·자산·직장 좌표·자녀 정보)을 DB에 저장하지 않는다. API 요청 본문으로 수신해 1회 계산 후 즉시 폐기한다.
- [ ] 통근 캐시(`CommuteCache`)에는 직장 좌표를 소수 3자리(약 100m 단위)로 반올림한 키만 저장한다. 정밀 좌표는 저장하지 않는다.
- [ ] 향후 로그 또는 모니터링 시스템 추가 시 소득·자산 등 재무 정보가 로그에 포함되지 않도록 마스킹한다.

## 5. 데이터 소스

- [ ] 실거래가 데이터는 국토교통부 공개 API(공공데이터포털)만 사용한다.
- [ ] 네이버 부동산·직방·다방 등 민간 부동산 포털을 크롤링하거나 스크래핑하지 않는다.
- [ ] 외부 데이터 소스를 추가할 경우 해당 데이터 제공자의 이용약관을 확인하고 `docs/data-sources.md`에 근거를 기록한다.

## 6. 향후 기능 추가 시 주의사항

새 기능이 아래 항목에 해당하는 경우 법무 또는 컴플라이언스 담당자와 사전 협의합니다.

- 특정 은행·금융상품 연동 또는 금리 비교 기능
- 가격 예측 모델 또는 투자 수익 시뮬레이션
- 개별 매물 정보 표시 (호·동·층 특정)
- 사용자 재무 정보의 서버 저장 또는 분석 활용
- 부동산 광고 상품 연동

---

이 체크리스트는 제품 변경 시마다 검토하고, 필요하면 항목을 추가합니다. 최종 법적 판단은 전문 법무 자문을 기준으로 합니다.
